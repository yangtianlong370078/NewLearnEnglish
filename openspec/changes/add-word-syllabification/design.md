## 上下文
`lexiconDeatil` 从词典详情服务获取数据后直接返回给前端。CMU 词典位于解决方案根目录 `CMU/cmudict-0.7b`，现有 `PhoneticsHelper` 仅供旧的 Whisper 模块使用，且每个实例会同步加载文件，不能复用到 WebApi 的请求路径。

## 目标 / 非目标
- 目标：启动期间仅加载一次 CMU 词典；优先返回 CMU 驱动的音节；未命中时用内置英文规则拆分；对现有词典详情字段保持兼容。
- 非目标：不将音节结果写入 MongoDB 或 Redis；不替换已有 Whisper 的 `PhoneticsHelper`；不更改词典详情的来源流程。

## 决策
- 在 `LearnEnglish.Application` 定义 `ISyllableService`，在 `LearnEnglish.Infrastructure` 实现为单例服务。构造函数读取并解析 CMU 文件，以只读字典常驻内存；因此不在请求过程中执行文件 I/O。
- 服务输出为 `IReadOnlyList<string>`。CMU 条目包含 ARPABET 音素而非原始字符边界，因此实现按发音元音（带或不带重音数字）划分音节，并将原单词字符按顺序映射到对应的音节数量；CMU 仅用于确定音节数与边界优先级。
- 若 CMU 无该词条或无法构建有效拆分，调用内置英文规则拆分器作为兜底。该拆分器基于元音核与相邻辅音边界；空白或非拉丁词条返回空数组。由于 Natural.NET 在 NuGet.org 上不存在可安装版本，无法调用其 `Syllabifier` API。
- 使用 `IOptions<SyllableOptions>` 配置字典相对路径；WebApi 将 CMU 文件设置为内容并复制至构建输出和发布产物，以避免机器绝对路径依赖。
- `WordController.lexiconDeatil` 通过注入音节服务并在有详情数据时计算 `syllables`，将该字段附加到现有 `data` 对象。该字段不持久化，以保持缓存和数据库实体不变。

## 风险 / 权衡
- CMU 不包含全部词形、专有名词和短语；内置规则提供确定性的兜底，但结果可能不同于词典发音。→ API 始终返回数组，前端可直接展示。
- 启动加载会增加一次性内存与启动时间。→ 词典只解析一次，并用单例承载，换取请求期间无磁盘读取。
- 规则兜底结果可能与词典发音不同。→ CMU 命中始终优先，并以单元测试锁定常见词的结果。
